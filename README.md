# DanceFactory / 舞形工坊

DanceFactory（舞形工坊）是一款**免费、开源、跨平台**的舞台队形编排工具。它主要为以下用户开发：

- LoveLive! 等偶像企划的翻跳团、舞见团体和 Coser 团体；
- 需要提前设计站位与换位节奏的舞团、校园舞社和唱跳组合；
- 负责排练统筹、走位记录和演出沟通的编舞、队长与舞台负责人。

软件把“谁在什么时间站在哪里”放到同一个编辑器中：导入排练音乐和参考视频，在舞台上安排成员位置，再通过关键帧或 F 拍打记录队形保持与变化的时间。排练成员可以直接看预览理解走位，不必只依赖手绘站位图或口头说明。

全部功能均可免费使用，源代码按 [GPL-3.0-or-later](LICENSE) 许可证公开。Windows 电脑版和 Android 手机版共用同一套核心编排思路，不需要购买会员或订阅才能使用完整功能。

**[访问舞形工坊官网、下载软件与阅读 Wiki](https://dfworkshop.top/)**

## 核心能力

- 图形化舞台：拖动舞者安排站位，支持网格吸附、C 位线、方向翻转和姓名显示。
- 时间轴编排：结合音频波形创建关键帧，并自动生成相邻队形之间的移动过程。
- F 拍打：播放时跟随节拍按下和松开 F，直接记录“保持队形”和“变化队形”的时长。
- 媒体对照：同时导入排练音乐和参考视频，边看原舞边编排。
- 舞者管理：设置姓名、编号、颜色和自定义形象，清楚区分每位成员。
- 预览与导出：检查完整走位，保存工程、共享工程包并导出队形演示视频。
- 双端使用：在 Windows 上精修，在 Android 横屏设备上排练、查看或现场调整。

### 本机自定义人员预设

电脑版通过 **预设 → 自定义预设** 创建或编辑本机模板：输入人数，批量生成舞者后填写姓名和颜色，再保存预设名称。JSON 自动保存到 `用户文档/FormationTool/Presets/custom-teams.json`。

预设只在点击“应用到当前工程”时展开为普通舞者；姓名、颜色和站位直接保存在工程里，不保留对预设文件的引用。换电脑、换手机或打开工程包时不需要模板文件。应用模板会替换各队形的人员，支持一步撤销。

## Windows 电脑版

![Windows 电脑版编辑器](docs/images/readme/windows-editor.png)

电脑版适合精确时间轴编辑、键盘快捷键和最终导出。编辑器由参考视频、中央舞台、舞者与关键帧列表、底部音频时间轴组成。

### 创建与管理舞者

![Windows 创建舞者](docs/images/readme/windows-add-dancer.png)

点击右侧舞者列表下方的 `+` 创建舞者并设置名称、编号和颜色。选中舞者后可拖动站位、编辑自定义形象或删除；所有站位变化都会记录到当前关键帧。

### F 键拍打

播放音乐时可以直接跟随节拍操作：

1. 按下 `F`：建立关键帧并进入绿色“保持队形”区间。
2. 松开 `F`：进入红色“队形变化”区间。
3. 再次按下 `F`：建立下一关键帧并开始新的保持区间。
4. 按空格暂停：保存当前区间并自动补充结束帧。

拍打完成后，可以在时间轴上继续微调每个红绿区间。

### 标准区间模式与台下

时间轴旁边的模式开关可以在 **F 拍打模式** 和 **标准模式** 之间切换，新建工程默认使用标准模式。标准模式将固定队形显示为区间，区间之间显示过渡；点击 `+ 队形` 新建并继承前一队形的站位，拖动角色只修改当前队形。拖动边界调整区间长度，点击过渡段修改变到下一队形所需的时间；队形菜单支持删除。未导入音乐时也可以先编排队形。切换模式保留原来的站位和时间设置，播放时暂停后再切换。

在 **舞台设置** 中开启台下后，舞台左右两侧显示半透明的“台下”区域，可将角色拖入或拖出。新建角色会自动开启台下区域，并放在左右台下交替排列。关闭开关只隐藏区域，不改变站位。模式与台下开关随工程保存，并支持撤销。

### 快速操作

![Windows 右下快速操作](docs/images/readme/windows-quick-actions.png)

快速操作集中在编辑器右下角，包括：

- 对齐网格：整理当前关键帧中略有偏差的站位。
- 快速编队：根据舞者人数生成预设队形。
- 清除选择：取消当前舞者选择，不删除数据。
- 显示名字：显示或隐藏舞台上的舞者姓名。
- 复制前帧：把上一关键帧站位复制到当前时间。
- 复制/粘贴关键帧：在不同时间点复用完整队形。
- 显示 C 位线：检查中心位和左右对称。
- 翻转方向：切换观众视角与舞者视角。
- 自动吸附：控制拖动时是否吸附到舞台网格。

## 电脑版日志与视频排查

电脑版启动后会自动保存本机运行日志，默认位置是 `%LOCALAPPDATA%\FormationTool\logs`，该目录无法写入时会尝试系统临时目录。日志使用 UTF-8 编码，每份约 2 MB，单个日志组最多保留 5 份。

发生错误时，可点击弹窗里的“打开日志文件夹”；平时也可从“帮助 → 打开日志文件夹”进入。请在复现问题后把文件夹内的 `.log` 文件发给维护者。日志只保存在本机，软件不会自动上传。

视频默认使用应用内置 **libmpv** 播放，视频和声音共用内核时钟；JavaFX 负责界面显示。无需另外安装 mpv、VLC 或系统解码包。暂停拖动使用精确定位，连续拖动合并为最新目标。

旧的 JavaFX 视频播放器、格式探测、代理播放和调试入口已移除；JavaCV/JavaCPP 依赖也已移除。JavaFX 媒体模块仅用于纯音频及兼容播放的 PCM 声音。

主播放组件加载或解码失败时，会自动改用独立 **FFmpeg 兼容播放**；兼容画面跟随提取的 PCM 音频时钟。主预览上限为 1280×720，兼容预览为 640×360；均保留原始比例，导出仍读取原片。工程不保存对播放内核或本机预设的依赖。

日志包含播放内核版本、组件路径、媒体路径、加载失败和自动兜底记录。两条路径均失败时，会在后台检查视频前 3 秒的 FFmpeg 解码结果；这项检查不代表整段视频一定正常。旧版转换产生的临时视频仍位于 `%TEMP%\video_时间戳.mp4`，新版导入不再因 JavaFX 不支持而要求整片转换。

## Android 手机版

![Android 手机版编辑器](docs/images/readme/android-editor.png)

手机版采用横屏触控布局，适合排练现场快速查看和调整队形。左侧导入参考视频，底部导入音频，中央舞台可直接拖动舞者；顶部提供复制前帧、撤销、预览、捕捉和 3D 功能。

舞台右下的圆形 `F` 按钮对应电脑版键盘 `F`，按住、松开和再次按住同样可以实时建立红绿变化区间。

### 手机版创建舞者

![Android 手机版创建舞者](docs/images/readme/android-add-dancer.png)

导入媒体后点击右上角“舞者 +”，可以填写名称、选择代表色，也可以直接选择 μ's、Aqours、虹咲学园、Liella! 或莲之空的成员名称预设。长按已有舞者可以继续编辑。

## 构建环境

- Windows 10/11 x64
- JDK 21（Android 模块也可使用 JDK 17）
- Android SDK（具体 API 级别以 `app/build.gradle` 为准）

仓库包含 Maven Wrapper 和 Gradle Wrapper，不需要单独安装 Maven 或 Gradle；首次构建会自动下载依赖。

## 获取源码

```powershell
git clone https://github.com/SnowfallC/dancefactory.git
cd dancefactory
```

## 构建 Windows 电脑版

```powershell
.\mvnw.cmd test
.\tools\prepare-playback-runtime.ps1
.\mvnw.cmd package -DskipTests
.\build-exe.bat
```

构建后的 JAR 位于 `target/`，包含运行时的 Windows 分发包位于 `dist/windows/`。文件名会随发布版本变化。

Windows 发行压缩包需要 Python 3.11+，打包时只收录程序、运行依赖及许可证；开发说明和验证报告留在工作目录。

`build-exe.bat` 自动下载并校验固定版本的 libmpv，组件及许可放在应用的 `app/native/mpv/`。单独运行 Maven 打包前需先执行准备脚本。播放内核对比与复测方法见 `docs/playback-comparison-20261020.md`。

## 构建 Android 手机版

配置 `ANDROID_SDK_ROOT` 后运行：

```powershell
.\gradlew.bat :app:lintDebug :app:assembleDebug
.\gradlew.bat :app:assembleRelease
```

- Debug APK：`app/build/outputs/apk/debug/app-debug.apk`
- Release APK：`app/build/outputs/apk/release/`

未提供本地签名配置时，Release APK 为未签名产物。官方签名与发布由项目维护者单独处理。

两端自动更新使用 R2 托管的签名清单。维护者的登录、打包、密钥备份与发布步骤见 [R2 发布说明](docs/r2-releases.md)。1.1.5 及更早版本需要手动安装一次 1.1.6，完成更新签名密钥迁移。
